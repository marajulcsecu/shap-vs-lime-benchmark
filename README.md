# SHAP or LIME? Agreement, Stability, Faithfulness and Speed Across Six Models and Three Clinical Datasets

[![CI](https://github.com/marajulcsecu/shap-vs-lime-benchmark/actions/workflows/ci.yml/badge.svg)](https://github.com/marajulcsecu/shap-vs-lime-benchmark/actions/workflows/ci.yml)
[![Python 3.12](https://img.shields.io/badge/python-3.12-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/code-MIT-green.svg)](LICENSE)
[![Pre-registered](https://img.shields.io/badge/protocol-pre--registered-8A6A33.svg)](docs/PROTOCOL.md)

A controlled comparison of the two dominant post-hoc explainers on clinical tabular data,
measuring **agreement, stability, fidelity, cost, and plausibility** across 6 classifiers ×
3 public clinical datasets = **18 model–dataset cells**, **1,746 explained instances**, and
**11 hypotheses pre-registered in version control before any result existed**. It also
proposes and tests a **hybrid consensus method** — *fidelity-weighted rank fusion*, which
weights each explainer by the faithfulness it demonstrates on a disjoint calibration split —
against two published fusion baselines. The hybrid did not clear its pre-registered bar, and
RQ6 explains why.

Undergraduate thesis for **ENG 672 — Technical Communication and Writing**, Department of
Computer Science and Engineering, University of Chittagong.

| RQ1 | Do SHAP and LIME agree on feature rankings? | **Substantially, but not interchangeably.** Median Spearman ρ = 0.74, top-5 Jaccard 0.67; clears a pre-registered 0.50 bar in 15/18 cells, yet one of the five top features still differs. Agreement is *lowest* on the **easiest** task (CKD, ρ = 0.63 at ROC-AUC 1.00). |
| RQ2 | How stable are the explanations? | **Reproducible ≠ robust.** Tree SHAP's re-run CV is *exactly* 0, but its cross-refit agreement is 0.83 — the ranking moves when the model is refit on a resample of the same data. Perturbation robustness: 0.18 (SHAP) vs 0.65 (LIME). |
| RQ3 | Are they faithful to the model? | **Both, SHAP more so.** AOPC 0.260 (SHAP) vs 0.224 (LIME) vs **0.075 (random control)**. Both beat the control in 36/36 tests after Holm correction. |
| RQ4 | What does an explanation cost? | **SHAP is ~25× cheaper** — 0.0019 s vs 0.0462 s per explanation. Structural, not an implementation detail. |
| RQ5 | Do top features look plausible? | **The metric does not discriminate.** Both beat random; neither separates from the other. Pre-registered as the weakest measurement here. |
| RQ6 | Does fusing the two help? | **No, in 0/18 cells** (median effect -0.80). A pre-registered null result that follows from RQ1: substantial agreement leaves no complementary signal to exploit. |

## Two documents, two jobs

The **paper** is a 6-page IEEE conference submission: the argument, the four
methodological traps, and the evidence a reviewer needs, with 2 tables and 2 figures.
The **report** is the full-length treatment: every cell of every metric, all 14 figures,
all 15 tables, a literature review, and four appendices. They are independent LaTeX
sources — the report does not `\input` the paper's prose — so trimming one cannot gut
the other. The earlier 12-page paper is retained at tag `v1.0-extended-paper`.

## Quick start

```bash
make setup    # virtualenv from requirements.lock.txt (exact pins)
make data     # download the 3 datasets, verify SHA-256, vendor locally
make test     # full test suite (~240 tests)
make smoke    # entire pipeline, QUICK profile, ~5 minutes
make all      # FULL run (~2 h) then build paper, report, slides
```

`make smoke` runs every stage and produces every figure and table at reduced budgets,
watermarked `PROFILE=QUICK — NOT FOR REPORTING`. Use it to validate a change before
spending two hours.

## The load-bearing design decision

**Every number in every document is generated by code.** Tables are `\input` from
generated `.tex` fragments; figures are generated PDFs; even the headline numbers in the
abstract come from `\newcommand` macros in `tables/findings.tex`. Nothing is typed by
hand. Rerun an experiment and the documents change on the next `make docs`.

A test enforces it: `test_no_generated_table_contains_a_literal_nan` guards the output
surface, and the paper's prose carries no bare decimals that a reviewer could not trace.

## Pre-registration

`docs/PROTOCOL.md` fixes every research question, hypothesis, metric formula, statistical
test, significance level, and correction procedure. It was **committed in its own commit
before any commit containing a result**, so the repository history is itself the evidence
that the analysis was not adjusted after seeing outcomes:

```bash
git log --oneline --reverse | head -3     # protocol freeze precedes all results
```

Five amendments were made during implementation, each recorded in §10 with a date and a
reason. Three were triggered by tests catching genuine errors that would otherwise have
been invisible in the output:

- **A2** — a k-means SHAP background violated SHAP's own additivity by ~1 % on LightGBM
  cells, because averaging one-hot columns produces fractional values the model never
  sees. Fixed to real training rows.
- **A5** — BCa bootstrap intervals for *medians* could exclude their own point estimate,
  because BCa's jackknife acceleration assumes a smooth statistic. Switched to the
  percentile bootstrap for medians.
- **A1** — raw rank-biased overlap has a width-dependent floor (0.589 at 8 features,
  0.193 at 24), so it is not comparable across these datasets. Added a floor-normalised
  variant.

## Pipeline

```
stage1_performance  nested CV 5×3       -> results/performance.csv, best_params.json
stage2_explain      18 cells, checkpointed -> results/attributions/*.parquet
stage3_metrics      5 metric families   -> results/metrics_*.csv
stage4_stats        11 hypotheses       -> results/stats_*.csv
stage5_outputs      14 figures, 12 tables, manifest
```

Each stage reads only what earlier stages wrote, is independently runnable, and skips
completed work unless given `--force`. Stage 2 checkpoints per cell, so a crash at cell
15 does not discard cells 1–14.

## Environment notes

Two pins are forced by real incompatibilities rather than chosen:

- `numpy<2` — the numba chain `shap` depends on does not build against 2.x.
- `xgboost==2.1.4` — XGBoost 3.x serialises `base_score` as a JSON array string
  (`'[3.485342E-1]'`), which `shap` 0.49's `TreeExplainer` parses with a bare `float()`
  and crashes on. Substituting a model-agnostic explainer for XGBoost would have
  forfeited both the determinism measurement in RQ2a and a fair cost comparison in RQ4.
